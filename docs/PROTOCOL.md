# 协议摘要

BLE 名称：`AtomClip-S3U`。ESP32-S3 使用 BLE GATT，不支持经典蓝牙 SPP。

| 项目 | UUID |

| 服务 | a29bc101-12a5-4ea1-81a0-2c4dd9cd0001 |
| 写入 | a29bc102-12a5-4ea1-81a0-2c4dd9cd0001 |
| 通知 | a29bc103-12a5-4ea1-81a0-2c4dd9cd0001 |

帧：`ACB1` + 1 字节类型 + 4 字节小端载荷长度 + 载荷 + 4 字节小端 CRC-32。CRC 覆盖类型、长度和载荷。类型为 Data=1、ACK=2、Ping=3、Status=4、TypeJob=5、JobResult=6。

文本先严格 UTF-8 编码，再使用 AES-256-GCM。载荷含 16 字节消息 ID、12 字节 nonce、密文和 16 字节标签；消息 ID 作为附加认证数据。单条文本最多 16384 字节，NUL 和无效 UTF-8 被拒绝。

ACK 对消息 ID 和 ACK 类型执行 HMAC-SHA256 并截取 16 字节。只有剪贴板写入成功后才确认；发送方使用相同 ID 重试，接收方进程内去重。该去重不是跨重启的持久化历史。

键盘任务使用相同的认证加密封装。旧文字任务的明文头为 `{1, pasteFlag, 4}`，后接 GZip 文本。常驻接收窗口启动任务的完整明文只有 `{2, 0, 4}`，请求固件中预定义的 PowerShell 启动命令；不携带任意用户命令，不自动粘贴或执行剪贴板。状态第四字节为 1 时支持该固定指令，旧固件不启用相应按钮。

TypeJob 在内网接收程序在线时被拒绝，板上物理按钮可取消正在进行的键盘任务。JobResult 也经过认证。键盘完成结果仅代表按键报告已发送，不能证明目标窗口执行或粘贴成功。

0.5.0 新增任务，仍用 TypeJob=5 和 AES-GCM：`{3,0,gap}+ASCII` 为直接 HID 输入，允许 0x20–0x7E、LF、Tab，最多 16384 字节，不调用脚本、不写剪贴板；`{4,pasteFlag,gap,startupSeconds}+GZip` 增加 3–60 秒系统启动等待。Windows/Android 使用 gap=4 ms，固件允许 1–50 ms。直接键盘编码前 CRLF 规范为 LF，其他不支持字符拒绝。

0.5.1 Status 第七字节为 1 表示固件支持精确的短间隔等待；客户端才使用 1 ms 数据间隔，缺失则回退 4 ms。固定启动命令保持至少 4 ms。旧固件 waitSafe 的 delay(5) 会把小于 5 ms 的间隔实际向上取到至少 5 ms；本版按剩余等待时间精确切片，不改变启动等待余量。

0.5.2 Status 第八字节为 1 表示支持微软拼音任务；缺失时只开放旧格式兼容性试输。TypeJob 密文解密后 `{5,settleMs,gapMs}+UTF8`，无压缩；settle 20–200 ms、gap 1–50 ms。当前 0.2.0 整合客户端默认 settle/gap 为 80/4，可显式自定义为固件允许范围内的整数；默认不再使用此前的 35/1。正文及试输统一采用所保存参数。先验证完整 UTF-8/BMP/16 KiB，再执行；拒绝非 BMP、代理项、过长编码、控制字符（LF/Tab 除外）和 FFFE/FFFF。非 ASCII 发送 `vuc`+四位十六进制，等待 settle、空格提交、再等 settle。ASCII 连续段只切换一次中英；成功完成恢复“中”。中止不再发切换按键。

兼容性试输沿用 `{3,0,35}+ASCII("vuc4e2d vuc6587 ")`，旧直接键盘固件可识别。所有任务继续使用认证加密和认证 JobResult；完成只证明按键已发出，不能证明目标窗口、输入法状态或文字正确。纯 HID 不提供内网剪贴板读取能力。

0.5.4 增加 Status 第九字节为 1 的 GBK 能力标志。TypeJob 内部版本 6：`{6,downMs,gapMs,beforeMs,afterMs}+GBK`，下按/间隔 1–50 ms，Alt 前后等待 1–100 ms。客户端快速参数为 2/2/3/6，兼容为 8/8/15/30；任务前统一等待 3 秒。GBK 原始流中 ASCII 直接输入，双字节转为 16 位数值的十进制小键盘码，保持 Left Alt 直到整码结束。参数和完整流先验证；停止请求在字符边界检查，当前数字码完成并释放 Alt 后停止。

Windows/Android 使用严格 GBK 编解码并校验往返一致，拒绝不支持字符、私用区及存在跨实现差异的欧元单字节码，不做替换。有效流仅允许 ASCII 可打印字符/LF/Tab，或首字节 81–FE、尾字节 40–FE（排除7F）的双字节。最大 GBK 流 16384 字节；客户输入本身仍受 16384 UTF-8 字节上限约束。开发板无需 Unicode→GBK 编码表。

两种中文方法的新版界面试输均为 `病ABC123，中文!`，VUC 走真实版本 5 混排任务，GBK 走版本 6；旧三字节原始 VUC 试输接口保留协议兼容但不作为新界面的混排确认。用户逐字核对后手动确认，切换方法/速度、断线或失败后重置。版本 5/6 都不能读取目标剪贴板，成功回执不证明主机实际显示正确。

Status 第五字节为 1 表示支持直接 HID，第六字节为 1 表示支持可调等待；能力缺失时不发送新增任务。旧文字和固定窗口任务兼容。本版固件对旧文字任务采用 10 秒启动等待，旧固件自身仍使用原 3 秒逻辑。

Status 是就绪提示，不是端到端认证证明；应用只有收到正确的加密正文和认证 ACK，才宣告文本发送确认。USB / BLE 的 CRC 和分包解决传输完整性，不替代加密认证。

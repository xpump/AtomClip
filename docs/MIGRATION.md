# 0.2.0 升级与开发板绑定

0.2.0 引入 V2 设备绑定。0.1.0 固件须先升级并经物理 USB 添加绑定；已有 0.2.0 V2 固件且完成绑定的板无需重烧。Android 版本码 61，公开 APK 沿用原公开签名，不能与私人签名混用。

## 添加或使用已有开发板

1. “我的开发板 → 添加开发板”，用数据线接入正常运行的开发板，无需进入下载模式。
2. Windows 显示串口名称，只有一个明确的 Espressif USB 候选时预选；手机只有一个可用原生 CDC 设备时直接读取，多设备必须选择。型号和身份以读取的完整 Info 为准，不通过 VID/PID 猜测。
3. 点击“读取开发板”，查看名称、型号和完整编号，确认添加。已在本机绑定的板显示“使用已有绑定”，只核对原密钥，不重复生成绑定；待确认记录优先核对上次结果。
4. 现有正文配对自动保留，原先已工作的内网程序和 PowerShell 配对不因再次添加而改变。板上有其他控制绑定时须明确确认替换。
5. 移板至内网，在列表选择后点击“连接”。“扫描附近”读取完整编号后合并显示，不会按短号、名字或信号自动认领；连接时仍验证身份。

## 从旧固件升级

新版已移除旧固件兼容连接，需要先升级至 0.2.0 配套固件。断开其他客户端，按厂家说明进入下载模式，核对型号与容量。首次安装或分区不兼容时必须明确选择清空安装；已有 V2 绑定先加密导出备份。写入及逐段校验成功后拔插，按上述步骤添加。

需要保留原内网 EXE 的正文配对时，使用对应私人或公开 AtomS3U 迁移套件；该固件首次初始化提供原配套正文密钥，客户端添加时保留。清除板上绑定会生成新的正文配对，不能靠重新添加恢复已清除的旧密钥。通用内网 EXE 可通过物理 USB 读取新正文配对，无需逐板编译。

## 多客户端共享与恢复

在可信客户端的“更多”中加密导出 `.acbind`，在另一台 Windows / Android 导入，使用同一份绑定。不要在两台客户端分别重新改绑。Windows DPAPI / Android Keystore 本机存储文件不可直接跨设备复制。

写密钥前先持久保存待确认记录。掉电或丢失回执后重新添加可核对原记录；尚未提交时通过“更多 → 重试待绑定写入”继续。待确认期间不能正常连接。恢复已有配置、导出、更名及忘记本机记录也在“更多”中。

分区兼容的普通升级保留 NVS。清空安装或清除绑定后，可通过 USB 恢复已备份配置。忘记仅删除本机记录，不改写板卡。

## 验证边界

桌面协议和模拟测试不能证明实机流程通过。手机布局、软键盘、字体缩放、Keystore、USB 权限、OTG、BLE 多板识别、烧录、NVS 掉电保持和目标输入法仍待硬件验证。USB 键盘只单向输入，不能读取内网剪贴板。

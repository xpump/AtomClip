# AtomClip 0.2.1 使用说明

## 1. 新开发板初始化

已有正常绑定的 0.2.0 开发板可直接更新客户端，跳到下一节。首次初始化的板先按 [板型支持表](BOARDS.md) 核对型号、SPI NOR 容量和原生 USB；Android OTG 说明见 [ANDROID.md](ANDROID.md)。

1. Windows 外网程序 → 开发板设置，选择准确板型。根据厂家步骤进入 ROM 下载模式；AtomS3U 长按 RESET 约两秒，通用板按自身说明操作。
2. 刷新并选择正确 USB 串口。程序检查 ESP32-S3、4 / 8 / 16MB 容量、OPI、分区和文件摘要。
3. 普通升级在分区兼容时保留 NVS 绑定区；首次安装或分区不兼容，先加密备份绑定，再明确选择清空安装。
4. 按清单写入四个固件段并逐段校验。完成后拔插开发板，保持正常运行模式，然后添加绑定。

固件、离线工具和摘要已内置，无需网络或另装 Python。不要将分段文件当作完整 Flash 镜像写入。

## 2. 添加并连接开发板

1. 保持板接在外网 USB，打开“我的开发板 → 添加开发板”。Windows 选择 USB 串口，手机多设备时选择目标。
2. “读取开发板”后查看完整编号和名称，点击“确认添加”。已绑定板显示“使用已有绑定”，只核对配置；已有正文配对自动保留。
3. 将板移到内网，在“我的开发板”选择后点“连接”。附近扫描会读取完整编号，与本机绑定合并显示，不会按短号或信号自动认领。
4. 导入、导出、更名、恢复和清除操作在“更多”。第二台客户端应导入同一份加密配置，避免重新改绑。

系统无需将板配成蓝牙键盘，不使用经典蓝牙串口。手机和 Windows 外网端一次只连接一个。新版不再提供旧固件兼容连接，迁移步骤见 [MIGRATION.md](MIGRATION.md)。

## 3A. 有内网程序

1. 将同一套构建的 `Windows/USB/AtomClipUSB.exe` 放到内网，双击运行。它是免安装单文件程序，依赖系统已有的 .NET Framework 4.8。
2. 选择开发板的 USB COM 端口，点击 **连接**。
3. 外网选择 **有内网程序**，等待“已就绪”。
4. 外网编辑文本，点击 **发送到内网剪贴板**。收到写入确认后，内网按 **Ctrl+V**。
5. 内网新复制的纯文本自动发送到外网剪贴板。外网复制即发送默认关闭，需要时勾选 **自动发送外网新复制的文字**。
6. 如果文字在连接就绪之前已复制，点击内网 **发送当前内网剪贴板**，或就绪后重新复制。外网收到文字会显示已写入外网剪贴板和字节数；内网日志只有收到认证回执才记发送成功。

## 3B. 无内网程序

“无内网程序”下有 **PowerShell / 仅 USB 键盘** 两个子选项。PowerShell 需允许系统 PowerShell、Add-Type 和 USB 串口。设置后默认双向，在内网接收窗口按 **B** 关闭或恢复内网回传，无需重新初始化。各界面保留自己的草稿，切换后自动发送关闭。

外网选择 **无内网程序 → PowerShell**，点击 **设置剪贴板同步**。每页只执行当前步骤：

1. **准备启动内容**：内网按 Win+R，再按 Win+空格选择系统 **ENG 英语键盘布局**，关闭 Caps Lock。清空运行框并保持打开。设置启动等待（默认 10 秒，慢电脑可设 20–30 秒，范围 3–60 秒），再点击 **写入启动内容**。界面显示已用时间及按任务大小估算的时间范围，期间不要操作内网键鼠。完成以开发板回执为准，不是倒计时归零。配套固件支持可调启动等待。
2. **打开接收窗口**：内网再次准备 ENG 空白运行框，在外网点击 **打开内网接收窗口**。开发板输入固定的系统 PowerShell 启动命令。
3. **粘贴一次**：在内网新打开的 PowerShell 窗口内按 **Ctrl+V**，再按 **Enter**。等待“选择开发板”窗口；粘贴内容含配对信息，不应截图或分享。
4. **选择开发板**：下拉列表选择 **USB 串行设备**对应的 COM 端口，再点击连接。接收窗口显示“开发板已就绪”、外网显示“已就绪”后，点击完成设置。

此后外网输入文字 → 发送 → 等待确认 → 内网 Ctrl+V。无需再次打开运行窗口。设置完成后默认双向，直接到原应用重新复制内网文字即可回传。内网接收窗口按 **B** 关闭或恢复内网回传；外网发送不受 B 开关影响。按 **P** 暂停或继续两向传输，按 **Q** 退出。窗口可最小化；关闭、退出登录或重启后需重新设置。

启动前、离线和暂停期间的旧剪贴板不补发。系统接收器只在窗口显示状态；Windows EXE 和 Android 分别保存状态日志。

## 3C. 无 PowerShell，仅允许 USB 键盘

外网选择 **无内网程序 → 仅 USB 键盘**。Windows 及 Android 均保留两种中英文方案，默认 GBK；不安装内网程序，不运行 PowerShell，不修改注册表或系统区域设置。

| 方式 | 内网准备 | 适用与限制 |
| --- | --- | --- |
| **中英文 · GBK 高速** | ENG 美式、Num Lock 开启、关闭大写锁定 | 汉字转成 GBK 的 Alt 数字码，英文和数字直接输入；绕过拼音候选处理。依赖系统和目标窗口的数字码语义，可能乱码，可先试输 |
| **中英文 · VUC 微软拼音** | 微软拼音全拼“中”、半角、默认 Shift 中英切换、关闭大写锁定 | 汉字和标点用 Unicode 码位；连续英文段切到英文直接输入，正常结束恢复“中”。支持 BMP，部分扩展汉字和多数 emoji 不支持 |
| **纯英文 · 直接键盘** | ENG 美式、关闭大写锁定 | 保留 ASCII 英文、数字、符号、换行、Tab；遇到中文可点击“切换到中英文输入” |

1. 用始终可见的 **GBK 高速 / VUC 微软拼音 / 纯英文** 按钮选择方式，并在内网准备好输入法和光标。GBK、VUC 均支持中英文混排。
2. 默认直接显示正文，可输入或粘贴文字，点击 **输入到内网窗口…**。开始后保留 **3 秒**准备时间。
3. **试输可选**：可随时点击“试输中英文”。勾选 **发送前先试输（可选）** 后，必须核对 `病ABC123，中文!` 并勾选结果正确，才展开正文。未勾选时无需试输确认，可直接发送。
4. GBK 乱码时选择 VUC；两种方式都不会静默替换或跳过不支持字符。GBK 不能无损编码时会提示改用 VUC。GBK 漏字可启用 **兼容速度**。VUC 默认已使用 4ms 按键 / 80ms 确认等待，可点 **自定义速度** 修改、保存或恢复兼容速度，调快后建议先试输。
5. 切换方式/速度、断线或失败会清除试输确认，草稿保留；仅在启用试输检查时要求重测。VUC 中止后须重新核对“中”；GBK 按完整数字码边界停止并释放 Alt。

**0.1.0 为整理发布号。** 本机固件与开发版 0.5.4 / 0.5.5 相同，已刷者无需重烧；原内网 EXE 仍兼容。新包内网 EXE 为 **57344 字节（56 KiB）**，统一版本与帮助，传输功能不变。试输可跳过，所选方式仍需对应固件能力；新板或能力缺失时用 Windows“开发板设置”更新。

正文上限 **16384 UTF-8 字节**，CRLF 规范为 LF；GBK 在外网/手机端转换，开发板不包含中文编码表。英文、数字、中文标点、换行、Tab 均保留顺序；Tab 和换行会操作目标窗口，先在纯文本框验证。不支持非 BMP、NUL、孤立 CR 等字符。实际兼容性取决于输入法、键盘布局和目标程序，试输通过后也应先发短文再发长文。

速度参数减少软件等待，不承诺任何设备达到某个字数/分钟。GBK 的高速路径与此[参考项目](https://zidongdazi.pages.dev/tutorial/)采用同类数字码思路，本项目保留 BLE 与原有剪贴板功能，未直接更换为对方 Wi-Fi 固件。

微软官方说明及示例确认全拼 V 模式提供 Unicode 输入（`vuc7389` 输入“玉”）：[微软拼音](https://support.microsoft.com/zh-CN/Windows/Hardware/Input-Devices/microsoft-simplified-chinese-ime)。实际内网兼容性以试输为准。

这是外网到内网的单向文本输入，不是剪贴板同步。USB 键盘不能查询宿主电脑剪贴板；在禁止 EXE、脚本和浏览器的条件下，本硬件不能完成内网回传，也不能可靠直接输入任意 Unicode。若必须双向，需要允许受控 USB 程序或系统桥接代码。

## 准备时间与慢电脑

“快速输入”把启动后的数据间隔设为 1 ms；固件修复了旧等待循环至少 5 ms 的限制。关闭该选项使用 4 ms 兼容间隔。短启动命令仍保持至少 4 ms，启动等待也保留。配套固件支持快速与兼容两种节奏。若内网出现漏字，先核对窗口和输入法，再关闭快速输入、增加启动等待后重试。

这缩短的是软件施加的额外等待，不保证真实电脑的总耗时提升某个倍数；USB 报告、系统处理及启动时间仍影响结果。

原固件只等约 3 秒便向 PowerShell 输入，慢启动可能丢失前部数据。本版默认 10 秒启动等待，冷启动或内网扫描慢时可设 20–30 秒。这是系统启动余量，完整准备还需要按键传输时间，不代表整个过程只需 10 秒。

界面按实际任务压缩后的字符数显示估算范围、已用时间，超时随任务大小调整。估算不含用户手动切换、粘贴和选择端口的时间，也没有获得物理电脑的就绪信号。若未出现窗口，先检查内网屏幕，再增加等待重新设置；不要盲目重复点击。按键发完不等于编译或剪贴板写入成功。

## 4. 验证发送与恢复

先使用无敏感内容的测试文字，例如三行“中文测试”“第二行 😀”“English 123”。

- 系统接收模式：发送一次，等待认证回执，在内网记事本粘贴，核对中文、多行和 emoji。
- 程序同步模式：按相同方法测试外网到内网；再从内网复制另一段文字，在外网记事本粘贴，核对反方向。
- 暂停后复制新文字，确认未被转发；恢复后重新复制或手动发送。已发出的任务不能撤回。
- 拔插板子后等待自动重连，随后重新复制或发送新文字。若系统分配了新 COM 编号，重启接收设置并重新选择。

## 常见状态

| 状态 | 处理 |
| --- | --- |
| 端口已打开，随后一直重连 | 仅代表 COM 能打开；核对是否选到 USB 串行设备，而非主板通信端口 |
| `Board status timeout` | 未收到 AtomClip 状态帧；核对端口、固件与 USB 连接 |
| 粘贴后出现解析错误 | 关闭失败窗口，用最新版重新执行初始化；不要复用旧剪贴板内容 |
| 烧录识别失败 | 关闭串口软件，重新进入下载模式，刷新并核对 USB 端口 |
| Flash 容量不符 | 本固件要求 AtomS3U / 8 MB，程序会停止写入 |
| BLE 已连，但接收器未就绪 | 检查内网接收窗口或 USB EXE 是否运行、COM 选择是否正确 |
| 发送未确认 | 核对内网剪贴板后再重试，避免误判重复发送 |
| 窗口关闭后仍运行 | Windows 主窗口关闭会进入托盘；右击托盘图标 → 退出，才会停止程序 |

## 日志

外网 EXE：`%LOCALAPPDATA%\AtomClipBLE\Logs`；内网 EXE：`%LOCALAPPDATA%\AtomClipUSB\Logs`。通过 **更多 → 查看运行日志 / 打开日志文件夹**访问。日志按日期保存，保留 7 天，单文件约 2 MiB 后轮换；不记录文本正文或配对密钥。

## 界面帮助

主窗口、接收设置和开发板设置窗口右上角的方形 **?** 按钮提供操作说明。主界面仅显示必要状态和操作，详细解释不会常驻占用界面。Android 主界面从 **更多 → 使用帮助** 进入，PowerShell 设置窗口保留问号帮助入口。

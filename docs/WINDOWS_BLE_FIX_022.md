# Windows 外网 0.2.2 连接修复

2026-10-19。只更新 Windows 外网程序 AtomClipBLE.exe；Android 和内网 EXE 保持 0.2.1，固件保持 0.2.0。无需重新导入、绑定或烧录。

## 原因与改动

用户导入有效绑定后，开发板插在内网电脑供电，外网一直显示连接或等待重连。本机日志反复出现 0x80070016（设备不识别此命令）。在用户断开当前程序、确认没有其他客户端后，诊断扫描发现目标广播，失败精确发生在 Windows `GetGattServicesForUuidAsync(..., Uncached)`。

同一开发板改用 `GetGattServicesAsync(Uncached)` 可成功枚举服务并读取完整 Info，固件 0.2.0、已配置控制绑定。环境为 Windows 11 build 26300、MediaTek Bluetooth Adapter，驱动 1.1038.0.443。此证据说明当前系统组合的按 UUID 服务查询路径失败，不代表所有同类适配器都有问题。

修复采用完整服务和特征枚举，再在客户端按固定 V2 UUID 严格选择唯一服务及 Info。完整设备编号核对、双向认证和 AES-GCM 会话均保留，没有旧协议降级或按名称认领。

连接界面现在显示扫描、读取完整编号、打开服务、订阅通知和身份认证阶段。失败原因保留在主界面，自动重试不再把它覆盖为泛化的“等待连接”。

## 使用

在旧程序的“更多 → 退出”中完全退出，再打开同配套的 0.2.2 外网 EXE。仅点击右上角关闭可能缩到托盘；旧程序仍运行时新版会提示先退出。当前本机运行的是公开配套，应使用公开配套修复版。

原绑定保存在本机受保护目录，换 EXE 后自动沿用。板可继续插在内网设备上。无需重新导入配置、改绑、修改 Windows 蓝牙设置或重烧固件。
